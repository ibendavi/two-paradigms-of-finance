Analysis Pipeline Quick Reference

Script Inventory

Trajectory Analysis (Keyword-Based)

Script Dir Input Output Runtime
Periodicals/analyze_trajectories_v2.py Periodicals/ Practitioner/, Academic/ txt files trajectories.json (keyword freq fields) ~15 min

Run:

cd "E:/Dropbox/Research1/EPS Literature/Periodicals"
python analyze_trajectories_v2.py

What it does: Counts 15 topic keywords per source-window (5-year periods). Computes two-pole paradigm score (pre-1920 practitioner vs. post-2000 academic cosine similarity difference). Outputs topic frequency tables and paradigm scores to trajectories.json.

Embedding Analysis

Script Dir Input Output Runtime
Periodicals/analyze_embeddings_v2.py Periodicals/ Periodicals txt trajectories.json (embedding_histograms), embeddings/*.npz ~4 hrs
Periodicals/analyze_embeddings_v3.py Periodicals/ Periodicals txt + JSONL Same + bridge journals ~4 hrs
Periodicals/analyze_embeddings_v4.py Periodicals/ Periodicals + Textbooks + Earnings calls Same + source_type_histograms, per-type npz ~8+ hrs

Recommended: use v4 for full analysis.

Run v4 (all sources, all topics):

cd "E:/Dropbox/Research1/EPS Literature/Periodicals"
python analyze_embeddings_v4.py

Run v4 (specific source + topic):

python analyze_embeddings_v4.py --sources textbooks --topics valuation capital_structure
python analyze_embeddings_v4.py --sources earnings_calls --topics earnings
python analyze_embeddings_v4.py --force valuation   # re-run even if already done

Available topics: mergers_acquisitions, valuation, capital_structure, payout, earnings, speculation, banking, insurance_risk, taxation, real_estate, accounting_reporting

Key architectural rule: Poles are ALWAYS computed from periodicals, even in v4. Textbooks and earnings calls are scored against the periodical-derived poles.

Embedding cache: Textbook text cached in Periodicals/textbook_text_cache/*.txt (MD5-keyed).

NPZ files: Periodicals/embeddings/{topic}.npz (all combined), Periodicals/embeddings/{topic}_{source_type}.npz (per source type, v4).

Script Dir Input Output Runtime

Run (full):

Recommended Full Run Order

When starting fresh or after major corpus additions:

  1. Download new data (if applicable): run download_*.py scripts, then merge_and_regenerate_txt.py
  2. Keyword trajectories: python Periodicals/analyze_trajectories_v2.py
  3. Pre-extract textbook text (v4 caches automatically, but can pre-cache): v4 does this on first run
  4. Embedding analysis: python Periodicals/analyze_embeddings_v4.py (long run, can do by topic)
  5. Discriminative terms: python Periodicals/analyze_discriminative_terms.py --earnings-calls
  6. Score textbooks: python website/score_textbooks.py
  7. Build website: python website/build.py
  8. Deploy: worktree approach above

Common Issues

Embeddings OOM on large topics: v3/v4 chunk encoding in batches of 50K (configurable via EMBED_CHUNK_SIZE). Uses show_progress_bar=False to avoid sentence-transformers' argsort that causes OOM on very large arrays.

OpenAlex type filter: Must use type:article not type:journal-article (taxonomy changed 2024).

Google Scholar rate limiting: Blocks after ~130 queries. Need to wait 1+ hour between sessions.

Elsevier abstracts: Elsevier pulled from OpenAlex Nov 2024. JFE/JCF/JBF have <10% abstract coverage. Use Scopus API (key: b9222cb69ba73e8b95b588098aca8c74, requires OSU VPN) for better coverage.

gh-pages deployment: Always use worktree approach. Never switch branches in main working tree.

Archive.org scanning: Use python/202602_scan_books_v21_playwright.py <identifier> for lending library books. Requires borrowing in browser first.
